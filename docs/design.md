# CutWise — Design Spec

## Overview

Single-page web app that optimizes lumber purchases by price. Takes a project's bill of materials and available stock, then recommends what to buy and how to cut it to minimize total cost.

Personal tool. No server, no accounts, no build step. Runs entirely client-side.

## Data Model

### Needed Pieces

What the user wants to build:

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| name | string | "" | Optional label (e.g. "Shelf top") |
| length | number (inches) | — | Required |
| width | number (inches) | — | Required |
| thickness | number (inches) | — | Required |
| quantity | integer | 1 | |
| canGlueWidth | boolean | true | Whether narrower strips can be edge-glued |
| grainSensitive | boolean | false | If true, piece cannot be rotated |

### Available Stock

What the user can buy. Three types:

**Dimensional lumber** — fixed cross-section, variable lengths (e.g. 1x6 in 6ft, 8ft, 10ft). Priced per piece.

**Hardwood boards** — specific length, width, thickness per board. Priced per board-foot. Cost per board = price × (length_in × width_in × thickness_quarters) / 144, where thickness_quarters is the quarter count (e.g. 4/4 = 1", 8/4 = 2").

**Sheet goods** — fixed dimensions (e.g. 4'x8' plywood). Priced per sheet.

Each stock entry:

| Field | Type | Notes |
|-------|------|-------|
| name | string | e.g. "1x6 Pine", "4/4 Walnut", "3/4 Baltic Birch" |
| type | enum | "dimensional", "hardwood", "sheet" |
| length | number (inches) | |
| width | number (inches) | |
| thickness | number (inches) | |
| price | number ($) | Per piece/sheet for dimensional/sheet, per board-foot for hardwood |
| quantity | integer or null | null = unlimited |

### Constraints (configurable with defaults)

| Constraint | Default | Notes |
|------------|---------|-------|
| kerfWidth | 0.125" | Blade waste per cut |
| minGlueStripWidth | 2" | Narrowest strip allowed in a glue-up |
| maxGlueJoints | 4 | Maximum joints per panel |
| overageMargin | 0.5" | Extra material per piece for squaring/sanding |

### Hardcoded Rule

**No end-grain glue-ups.** Pieces can only be made wider through edge-gluing, never longer. This is a structural integrity rule and is not configurable.

## Optimizer

### Interface

```
optimize(neededPieces, availableStock, constraints) → CutPlan[]
```

Returns 3 solutions ranked by total cost. Each solution contains:
- totalCost: number
- totalCuts: number
- purchases: list of { stock, quantity }
- assignments: list of { neededPiece, sourceStock, cutPosition, glueUp details if applicable }

### Phase 1: Greedy Algorithm (MVP)

First Fit Decreasing bin-packing:

1. Expand needed pieces by quantity (e.g. "Shelf top x2" → 2 entries)
2. Group needed pieces and stock by compatible thickness
3. Sort needed pieces by area, largest first
4. For each needed piece, try to fit into stock (cheapest first):
   - **Direct fit:** stock is wide and long enough (after kerf + overage)
   - **Glue-up fit:** if piece allows glue-up and no single stock is wide enough, check if combining narrower strips (same thickness) meets the width. Respect min strip width and max joints. Compare cost vs. wider stock.
   - **Sheet goods:** shelf-packing algorithm (rows left-to-right, bottom-to-top)
5. Track remaining usable material on each purchased board for later pieces
6. Score by total cost

To generate 3 distinct solutions, the algorithm varies strategy per pass:
- Pass 1: pure cheapest stock preference
- Pass 2: prefer wider stock (fewer glue-ups, fewer cuts)
- Pass 3: prefer fewer, larger boards (simpler shopping list)

### Phase 2: ILP Solver (future)

Replace greedy with glpk.js (WASM). Same interface. First result is provably optimal. Remaining 2 solutions generated by adding constraints (e.g. "cheapest with fewer than N cuts", "cheapest with no glue-ups").

## User Interface

Single-page app. Three sections top to bottom.

### 1. Needed Pieces (input table)

- Editable rows: name, length, width, thickness, quantity, canGlueWidth, grainSensitive
- Add/remove rows with buttons
- Support pasting tab-separated values (spreadsheet/CSV)

### 2. Available Stock (input table)

- Editable rows: name, type, length, width, thickness, price, quantity
- "Load presets" button for common dimensional lumber (2x4, 1x6, etc.) with placeholder prices
- Save/load named stock lists to localStorage

### 3. Results

- "Optimize" button
- Displays 3 solutions ranked by price, each showing:
  - Total cost
  - Number of cuts
  - Purchase list (what to buy, how many)
  - Cut assignments (which needed pieces come from which purchased board, with offcuts noted)
- User picks the one they want

### Settings Panel (collapsible)

Kerf width, min glue strip width, max glue joints, overage margin.

## Persistence

- **Stock lists:** saved to localStorage, named (e.g. "Home Depot prices", "Local lumber yard")
- **Projects:** saved to localStorage, named (e.g. "Bookshelf", "Dining table")
- **Export/import:** JSON file for backup or moving between devices

## Tech Stack

- Plain HTML + CSS + vanilla JS
- No framework, no build step, no server
- Single `index.html` (or small set of files) that can be opened from filesystem or hosted anywhere
- All computation runs client-side

## Future Enhancements (not in MVP)
